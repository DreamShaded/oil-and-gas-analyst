# Нефтегазовый аналитик

AI-агент в роли **Старшего аналитика нефтегазового рынка** с гибридным поиском
по отраслевым отчётам (RAG) и интернету, а также модулем прогнозирования цен на нефть.

Идея проекта вдохновлена [Ouroboros](https://github.com/joi-lab/ouroboros-desktop),
но переосмыслена в сторону **послушного аналитического инструмента**: фокус на пользе и верифицируемости,
а не на «свободной личности» агента.

## Данные

RAG-индекс наполняется из реальных публичных источников. Сбор командой `python main.py bootstrap`.

- **EIA** (US Energy Information Administration) — Brent/WTI spot и forecast, запасы и добыча США, SPR, refinery inputs, imports, мировые supply/demand, OPEC vs non-OPEC.
- **OPEC MOMR** — ежемесячные PDF (последние 6) с `opec.org` через Playwright.
- **OPEC WOO** — годовые PDF World Oil Outlook (последние 3) тем же путём.
- **IEA OMR** — публичные HTML-обзоры за последние 6 месяцев.
- **Минфин РФ** — месячный XLSX «Сведения о формировании и использовании дополнительных нефтегазовых доходов» с 2018 года, 18 метрик, 100+ месяцев.
- **Веб Tavily** — для свежих новостей и котировок, также когда в RAG данных недостаточно.

## Прогнозирование цен

Модуль `src/forecasting` строит точечный прогноз и доверительные интервалы на горизонт 1–24 месяца для Brent/WTI/Urals двумя методами. **SARIMA** (`statsmodels`, order=(1,1,1), seasonal=(1,1,1,12)) — авторегрессионная модель чистой ценовой динамики с сезонностью 12 мес.; требует ≥36 точек истории. **Ridge-регрессия по фундаментальным факторам** (`sklearn`, α=1.0) — линейная модель на стандартизованных признаках (запасы, добыча, OPEC-квоты, US rig count и т.п.) с **VIF-фильтром** (порог 10) для отсева коллинеарных факторов и поддержкой сценарных шоков («OPEC −2 мб/с» и т.п.); CI — bootstrap по остаткам (1000 итераций).

Доверительные интервалы по умолчанию заменяются на **conformal CI** — относительные квантили |error|/|y| из rolling-origin backtest с adaptive-инфляцией. Это инвариантно к уровню цены (нефть прыгала с $50 в 2015 до $120 в 2026, абсолютные ошибки несопоставимы).

Все прогнозы возвращаются с диагностикой (AIC/BIC для SARIMA, R² in-sample и стандартизованные коэффициенты для регрессии, список выкинутых VIF-факторов) и помечаются как **модельная оценка, а не торговая рекомендация**.

## Приоритизация источников

Граф агента сначала идёт в RAG, и только при недостаточном покрытии (heuristic ≥3 чанков выше порога) или intent=`web_only` («сегодня», «новости») — fallback на Tavily; каждый факт в ответе маркируется источником, при дублировании RAG приоритетнее web (см. `compose-answer.system.md` правило 4). Намеренные упрощения под сроки: `web_only` обходит RAG целиком (для запросов «цена прямо сейчас» индекс бесполезен), и sufficiency-check чисто числовой без LLM-судьи семантики. При наличии ещё небольшого количества времени реализовал бы.

## Стек и LLM-провайдеры

LLM-слой построен на **LangChain + LangGraph** и поддерживает любого провайдера из двух семейств: **OpenAI-совместимый API** (`langchain-openai` — родной OpenAI, Ollama, vLLM, LM Studio, OpenRouter, DeepSeek и пр.) и **Anthropic** (`langchain-anthropic` — Claude). Провайдер выбирается через `.env` без изменений кода. Выбор стека продиктован ТЗ: п. 2.2 требует **граф состояний агента** (classify → RAG/web → forecast → compose → reflect) — LangGraph даёт это из коробки с типизированным `State`, чекпойнтами и условными рёбрами, а LangChain — единый интерфейс к моделям и tool-calling (нужен для `propose_self_improvement` из п. саморазвития). **Qdrant** выбран под требование к векторному поиску с фильтрами по метаданным (источник/период/тип), **pymupdf4llm + pdfplumber** — под парсинг отраслевых PDF (OPEC MOMR, WOO) с сохранением таблиц, **statsmodels + sklearn** — под требование прогнозирования с интерпретируемыми коэффициентами и доверительными интервалами (п. 2.5), **Gradio** — под быстрый чат-UI без фронтенд-разработки (п. 2.6).

Демо построено на Antropic - считаю модель дорогой, но всё-таки одной из лучших и пользуюсь сам.

**Что выбрал бы альтернативно:** для production-нагрузки — **pgvector вместо Qdrant** (одна БД на всё — данные, метаданные, эмбеддинги; проще операционно, дешевле на малых объёмах), **time-series foundation models вместо чистой SARIMA** — zero-shot форкастеры, предобученные на миллиардах точек: **Chronos**, **TimesFM**, **Moirai**, **TimeGPT** (Nixtla, API). Они работают без переобучения на каждом активе, ловят сложные нелинейные паттерны. Поверх — **conformal prediction остаётся** как обёртка для калибровки, и **FastAPI + React вместо Gradio** для красивого UX и многопользовательской сессионности. Текущий стек выбран сознательно проще — он покрывает ТЗ за меньшее время и легче отлаживается соло-разработчиком.
